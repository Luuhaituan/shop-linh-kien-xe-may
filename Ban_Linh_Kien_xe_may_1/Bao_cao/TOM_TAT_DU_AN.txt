6. CÁC LUỒNG NGHIỆP VỤ QUAN TRỌNG
-----------------------------------
A) ĐẶT HÀNG:
   Giỏ hàng → Nhập thông tin → (Tùy chọn) nhập mã GG
   → Server validate mã → Tạo DonHang + MaVanDon (VD+timestamp)
   → Copy ChiTietGioHang → ChiTietDonHang → Trừ SoLuongTon
   → Xóa giỏ → Trả MaVanDon cho client
   → Nếu CK: SePay gọi webhook → Server đối chiếu → Cập nhật

B) CHAT HỖ TRỢ:
   Khách tạo PhienChat → Gửi TinNhan (DaDocKhach=1, DaDocNhanVien=0)
   → NV đọc (UPDATE DaDocNhanVien=1) → NV trả lời
   (Đánh dấu đã đọc riêng cho từng phía)

C) QUẢN LÝ ĐƠN (Admin):
   Xem DS đơn → Cập nhật trạng thái (có validate luồng hợp lệ)
   → Ghi LichSuDonHang + NhatKyHoatDong
   Trạng thái đơn: Chờ xác nhận → Đang chuẩn bị → Đang giao
                   → Đã giao (COD tự động "Đã thanh toán")
                   → Hoàn thành | Đã hủy (có lý do)

D) MÃ GIẢM GIÁ:
   Server check: tồn tại + đang bật + trong hạn + còn lượt
   + đạt giá trị đơn tối thiểu + user chưa dùng mã này
   → Tính TienGiam (PhanTram có GiamToiDa, SoTien cố định)
   → Khi đặt hàng thành công: UPDATE DaDung = DaDung + 1


7. ĐIỂM NỔI BẬT VỀ KỸ THUẬT
------------------------------
- Mô hình 3-tầng rõ ràng: ASPX (UI) → ASHX (API) → EDMX (DB)
- Phân quyền chi tiết theo từng tab chức năng
- Mật khẩu được hash (PasswordHelper) chứ không lưu plaintext
- Session["User"] lưu NguoiDung object (dùng MaNguoiDung để truy vấn)
- Tự động trừ tồn kho khi đặt hàng, có phiếu kho (PhieuKho)
- Đánh dấu đã đọc độc lập cho khách và nhân viên trong chat
- SePay Webhook tự động đối chiếu MaVanDon + số tiền
- Tất cả API đều trả JSON, validate Session trước khi xử lý
- Admin có nhật ký hoạt động (ghi IP) cho mọi thao tác
